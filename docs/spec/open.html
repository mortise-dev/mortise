12.1 Open questions for the owner

None are left. The owner answered all sixteen questions of the first version on 22 November 2026; the answers are decisions on the overview, section 1.1, each with its question number.

12.2 What the screens assume that does not exist yet

Read on 23 November 2026 from release 13.4.0 of nwidart/laravel-modules and release 1.3.1 of nwidart/laravel-actuator. Version 13.3.0 stays in the mock data, as the version of the app that is drawn. The first version of this list was read on 22 November 2026 from 13.3.0 and 1.0.0. Nothing in this list is invented as an API: no endpoint path, option name or JSON field is fixed by this spec. Each line says in words what a screen needs. The column "What exists today" starts with the state of each line: met, in part or not yet. Actuator 1.3.1 also has a migrations health indicator. It reports Out of service while migrations wait, for the whole app, so it does not give P4.

What needs nothing new. Phase 1 without the actuator needs no PHP and no package change: apps, modules, statistics, the Boundary graph, the rules and the findings on files. Phase 1 with the actuator uses four endpoints that exist since 1.0.0: health (exposed by default), and info, mappings and scheduledtasks, which the app must add to exposure.include and should protect with middleware. Mortise never requests env.

Assumed outside the packages. A coverage report in clover format exists in the app (otherwise coverage reads "unknown"). Git is installed (otherwise churn is absent). An editor command is set (otherwise "Open in editor" says so). A credential store is running on the computer (otherwise a secret is kept only until Mortise closes). Herd, Sail or Docker are detected from the folder; the exact commands in the drawings (herd php artisan, ./vendor/bin/sail artisan, docker compose exec app php artisan) are examples to be confirmed by the builders.

12.3 Not checked

  • No part of this was built in egui. Sizes, the joint, the floating scrollbar and the shadows are specified from the identity page and from reasoning about flat shapes, not from a prototype.
  • The custom title bar on each platform (macOS buttons over custom content, Windows 11 snapping, Wayland decorations) was not tested. Section 8 says what the design needs.
  • How Asap and Inconsolata rasterise in egui at 11.5 to 13 px on a 1x display was not looked at. The identity page already names this as a risk for Asap.
  • The drawings were rendered in Chrome at 1280 px wide, in both themes, and looked at. They were not opened in Safari or Firefox, and not at other widths apart from the two 960 px windows.
  • Contrast was computed from the token values and measured on the rendered drawings for text. Outlines and marks were checked from the token table only.
  • The four destructive commands were read in source on 22 November 2026, not run. Table names and counts in their dialogs are invented.
  • The public surface scan is a design. No parser was run on a module to see what such a scan really finds.
  • The package commands were read in source, not run. Output lines in the runner drawings follow the strings in the source; spacing and colours of real output will differ.
  • The actuator was read in its documentation and configuration file, not installed or called.
  • Screen reader behaviour was not tested; the claim about egui and AccessKit is from memory.
  • The Herd, Sail and Docker command lines were not run.
  • The font licences were read in the repositories linked in section 11. The font files themselves and their embedded licence fields were not opened.
  • The changes of 23 November 2026 (laravel-modules 13.4.0, laravel-actuator 1.3.1) were read in source. No package command was run, and nothing was installed.
  • The packages may change after 23 November 2026. Command names and options were read on 22 November 2026 from the local checkout, and the changes since then on 23 November 2026 in the releases named in 12.2.
