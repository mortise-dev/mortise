Phase. 1 for the folder and the runtime section. The "Run PHP with" section appears from phase 2.
Data. Versions from composer.lock. Modules from the module.json files and modules_statuses.json. Herd, Sail and Docker are detected from the folder: a Herd site link, vendor/bin/sail, a compose file. From .env Mortise reads two lines and no others: APP_URL, to prefill the base URL, and APP_ENV, to ask before a command in production. Test runs artisan --version and one request to the actuator.
Credentials. Four kinds: none, bearer token, HTTP basic, and a custom header with a name and a value. The actuator runs whatever middleware the app configures, and its viewActuator gate needs an authenticated user, which in Laravel is usually a token guard: hence the bearer token. Basic and a custom header cover a proxy in front of the app. All four are drawn in S8.5.
Secrets. A token, password or header value goes to the credential store of the operating system. It is never written to mortise.json or to Mortise's own config file, and after entry it is not shown again (S8.1).
Runtime is optional. The app is added without it. The section is hidden when composer.lock has no nwidart/laravel-actuator; the Summary then says how to install it.

5.2 App rail

S2.1App rail with 1 app and with 10 apps

Light, then dark. The rail is 52 px wide and never changes width.

Phase. 1.
Tile. 34 px square, 8 px apart. Two letter monogram: the initials of the first two words of the folder name, or its first two letters. If that is taken, the first two letters; if that is taken too, the first letter and the next free letter. The user can change it in Settings.
Pip. A 9 px problem mark on a tile means the app has at least one finding of the kind problem. Warnings do not raise a pip. Runtime status is not shown on the rail: apps that are not running locally are normal.
Order. The order apps were added in, changed by dragging or in Settings. Ctrl Alt 1 to 9 select the first nine.
Overflow. The add tile and Settings stay pinned at the bottom. When the tiles do not fit between them, the tile list scrolls with the wheel and with Up and Down; no scrollbar is drawn in a 52 px column, a 1 px line at the top or bottom edge shows there is more.
Outlines on frame. Tile outlines use ink-2, not line-2, which is under 3 to 1 on frame in the light theme (see Tokens).
Assumes. Nothing the packages lack today.

5.3 Module index

S3.1Module index: default, problems first, filtered, no match, a module turned off

The index column alone, 264 px wide. Use the theme switch for dark.

Phase. 1. "New module" in the footer appears from phase 2.
Data. Module list and on or off state from module.json and modules_statuses.json; files counted on disk; coverage from the last clover.xml; finding state from the checks in S6.4.
Header. App name, modules on, versions. The line with the stroke mark is the runtime status of the selected environment and is drawn only when one is connected.
Order. By name is the default because a module then keeps its place. S switches to problems first and back; the choice is kept per app. The shop-api drawings in the rest of the spec use problems first.
Finding state of a row. The worst finding of the module: problem with its count, warning, or good. A circular link is counted once, on the module with fewer files in the circle, because that is the cheaper side to cut; the other module shows the link in its Boundary tab.
Groups. Group names and membership are kept by Mortise per app, not by the package. Without groups the list is flat.
Assumes, not in the package today. Only the sixth drawing: P9 runtime status per module. Without it the row has one mark.
