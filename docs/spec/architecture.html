Information architecture

Mortise design specification, section 2. Navigation model, surfaces, data sources, phases.

Section 2 of the specification: how the app is laid out and moved through, every surface it has, where its data comes from, and what is on screen in each phase.

2.1 Navigation model

Three choices, left to right, each narrowing the next: an app on the rail, a row in the index (the whole app or one module), a tab in the workspace. The choice of tab is kept while moving through modules, so J and K with the Boundary tab open walk through the boundaries of every module. There is no back stack and no page navigation: the three choices are always visible, and Esc only ever closes the topmost thing.

Decision: tabs are shown, actions are hidden. The five tabs are in every build, in the same order with the same keys, because the keys 1 to 5 and the place of each tab should not move between releases. A tab whose phase is not built opens an explanation in the app's voice, with no fake controls (S7.4). Buttons, footer actions and palette entries of a later phase are left out, because a disabled button on every module is noise and a palette that lists what cannot run wastes the first result.

The same explanation block has a permanent use. In a build that has the phase, a tab still explains itself when this app cannot use it: PHP was not found, or the app's version of the package is too old. In that case the controls that exist are drawn disabled, each with the reason in its tooltip.

2.6 How it scales

SizeWhat changes
1 app, 5 modulesThe rail holds one tile and the add tile. The index shows every module without scrolling, two lines a row. The app graph is drawn whole.
10 apps, 60 modules eachThe rail lists ten tiles; the first nine have a shortcut and the palette reaches all. The index uses one line a row, groups, and "problems first" pins the modules that need attention. The app graph gives way to the table of links; each module keeps its own graph.
MoreThe rail scrolls, the index scrolls with a floating bar, tables scroll. Only visible rows are laid out.
