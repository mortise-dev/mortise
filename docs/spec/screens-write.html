Mortise design specification, section 5, part 3. Generate, Actions, runner drawer.

Theme for the switchable drawings on this page. Kept in memory only. Without JavaScript they stay light; the paired drawings always show both.

Section 5, part 3 of 4: everything that runs a command. Generate, Actions and the runner drawer. All of it is phase 2: it needs PHP, and several parts need additions to the package, named under each screen.

The rule for every command. The exact command is on screen before it runs, it can be copied instead of run, the files or rows it touches are named first where Mortise can know them, and the output is shown as the command wrote it.

What each command does, read in its source. module:migrate-reset rolls back every migration of the module that ran; options --pretend, --database, --subpath, --direction. module:migrate-refresh calls reset, then module:migrate, then module:seed with --seed; options --database, --seed; no dry run. module:migrate-fresh runs db:wipe on the whole database, creates the migrations table, runs the app's own migrations and then module:migrate for the modules named; options --database, --seed, --drop-views, --drop-types; it refuses --pretend. module:delete removes the module's line from the statuses file and deletes its folder; it does not touch the database.
Decision: dropping all tables is offered only for the whole app. For one module the command still wipes the whole database and then brings back only the app's tables and that module's, leaving the other modules without tables. On a module's tab the group says so: Dropping all tables is under "All modules". For one module the command would drop every table and bring back only the app's own and this module's.
Production. When APP_ENV is production Mortise does not run any of the four. The button is disabled, the reason is on the panel, and the command can be copied: shop-api reports the environment production. Mortise does not run this command there. Copy it and run it where you can watch the database.
If the app prohibits them. The package can refuse these commands. Module::prohibitDestructiveCommands() refuses the four and module:migrate-rollback. On master at 5b0307af each of the five also has its own flag, for example MigrateFreshCommand::prohibit() or ModuleDeleteCommand::prohibit(), so an app can refuse one and allow another. Mortise cannot know before running; it shows the refusal: The app prohibits this command, so the package refused to run it. Its message is quoted above.
